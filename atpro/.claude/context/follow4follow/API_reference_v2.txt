============================================================
1. BASE URL, HEADERS, ENVELOPE
============================================================

Base URL       : https://api.follow4follow.net
Web origin     : https://follow4follow.net
Response CType : application/json; charset=utf-8

Headers mặc định (INTERCEPTOR TỰ GẮN trên MỌI request — verified BEnDMXnR.js):
  Accept           : application/json
  Authorization    : Bearer <ACCESS_TOKEN>     ← interceptor: localStorage token; MỌI request
  Content-Type     : application/json           ← cho POST/PUT có body JSON
  Origin           : https://follow4follow.net
  Referer          : https://follow4follow.net/
  User-Agent      :Mozilla/5.0 (Linux; Android 10; K) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/139.0.0.0 Mobile Safari/537.36
  x-ts             : <Unix timestamp seconds>   ← interceptor tạo mỗi request
  x-sign           : <hex 64 ký tự>              ← interceptor tạo mỗi request

⚠ QUAN TRỌNG — 3 header BẮT BUỘC trên mọi request gọi API /user/*:
  1. Authorization : Bearer <token>   — thiếu → 401 "Chức năng này cần đăng nhập"
  2. x-ts          : Unix timestamp   — lệch giờ máy > ~60s → bị từ chối (chống replay)
  3. x-sign        : HMAC (mục 2)     — sai → từ chối
  → Tool f4f.py tự gắn cả 3 ở Client.request() cho MỌI request — xem panel
    "Chi tiết lỗi" trong tool để chứng minh headers đã gửi.
  Lưu ý: x-sign chỉ ký `{ts}:{METHOD}:{path}` — KHÔNG gồm body, nên thứ tự
  key trong body không ảnh hưởng chữ ký (nhưng body phải ĐỦ field).

============================================================
2. X-SIGN / X-TS — ĐÃ XÁC ĐỊNH HOÀN TOÀN
============================================================

Thuật toán (trích từ bundle Bfp0_r72.js, biến Pm):

  const Pm = "follow4follow_key";
  const t  = Math.floor(Date.now()/1e3);                 // = X-Ts
  const n  = `${t}:${METHOD.toUpperCase()}:${url.split("?")[0]}`;
  const a  = hex(HMAC_SHA256(key=Pm, msg=n));            // = X-Sign

Tương đương Python:

  import hashlib, hmac, time
  ts    = int(time.time())
  path  = path.split("?", 1)[0]
  msg   = f"{ts}:{method.upper()}:{path}".encode()
  sign  = hmac.new(b"follow4follow_key", msg, hashlib.sha256).hexdigest()

Bằng chứng khớp (ảnh DevTools POST /user/auth/login):
  X-Ts  = 1793087078   (= 2026-10-27 14:44:38 +07)
  X-Sign= 589b0d565bd8ce3db463535bbac382f55096350eb8de0df605dbcb0e84b8028e  ✅
          (sửa lỗi OCR: 'o' → '0')

Lưu ý:
- Pm là chuỗi hardcode trong bundle front-end, bất kỳ ai tải JS cũng thấy được.
  Vì vậy X-Sign chỉ là lớp chống bot/scan nhẹ; lớp xác thực thật là Bearer token.
- Path phải là path tương đối bắt đầu "/" (vd "/user/auth/login"), không full URL.
- Query string phải bị strip: ký "?" trở đi không nằm trong message.
- Method phải in hoa (POST, không post).
- Server thường chỉ chấp nhận X-Ts trong khoảng ±60s so với now (chống replay).

3. ENVELOPE RESPONSE
============================================================

Mọi response đều có cấu trúc:

{
  "status_code": <integer>,   ← có thể KHÁC HTTP transport status; cần kiểm cả hai
  "message":     <string>,    ← có thể rỗng
  "errors":      <null|object>, ← null khi OK; khi validation lỗi: {field: [msg,...]}
  "data":        <object|array|null>
}

QUAN TRỌNG:
- HTTP transport có thể = 200 nhưng JSON status_code = 400 (đã quan sát).
- data có thể là object, array, hoặc null.
- Endpoint phân trang: items nằm ở data.data (lồng thêm một lớp).

ENVELOPE PHÂN TRANG (dùng chung bởi mọi endpoint list — transaction/withdraw/
account/transfer/earn-coin/list/order/refill-list/support…):

{
  "status_code": 200,
  "message":     "",
  "errors":      null,
  "data": {
    "data":         [ ...items... ],   ← MẢNG item (có thể rỗng [])
    "per_page":     10,
    "total_page":   1,
    "current_page": 1,
    "total":        0
  }
}

→ Khi data.data = [] và total = 0: HỢP LỆ (không phải lỗi) — nghĩa là "chưa có
  dữ liệu/trang này trống". Tool v1.6 hiển thị "∅ Không có dữ liệu — trang 1/1
  · tổng 0" thay vì dump từng field như bản cũ.

3.1  CÁCH TOOL v1.6 HIỂN THỊ RESPONSE (smart viewer)
------------------------------------------------------------
- Nhận diện envelope phân trang ở trên → render BẢNG danh sách item + dòng meta
  "trang x/y · tổng N · M/trang"; danh sách rỗng → panel "∅ Không có dữ liệu".
- data là dict thường → bảng Trường/Giá trị (flatten dict lồng, che token).
- data là mảng dict → bảng các cột; mảng rỗng → "Không có dữ liệu".
- Field kèm cạnh mảng (vd accountActive, account_daily_usage trong /user/earn-coin)
  → hiển thị thêm bảng phụ "— thông tin kèm" (không bị mất như bản cũ).
- KHÔNG còn hỏi "Xem JSON thô? [y/n]" sau mỗi request — thay bằng 1 dòng:
  "Enter = tiếp tục · j = JSON thô" (chỉ bấm j khi cần đối chiếu DevTools).
- Lỗi (HTTP>=400 hoặc JSON status_code>=400 hoặc errors khác null) → thêm panel
  "Chi tiết lỗi" kèm chứng minh 3 header đã gửi (x-ts / x-sign / Bearer).

5. QUY TẮC PARSE RESPONSE CHO TOOL
============================================================

1. Đọc HTTP status của response.
2. Parse JSON body. (Nếu không parse được, lưu raw text.)
3. Kiểm tra body.status_code (nếu có), body.errors, body.message.
4. Chỉ đọc body.data theo schema riêng của endpoint; KHÔNG giả định data luôn là object.
   - /user/auth/me               → data = object
   - /user/account/list         → data = object { data: [...], per_page, ... }
   - /user/leaderboard          → data = object { leaderboard: [...], my_rank }
   - /user/job-rewards          → data = array trực tiếp (không lồng)
   - /user/withdraw/list        → data = object { data: [...], meta, links }
5. Che access_token, Authorization, X-Sign, X-Ts, username, email, ref_code, uid,
   avatar URL khi log — không bao giờ in ra file hoặc console.
6. Với POST pass-through (login, changePassword, withdraw*, transferCoins, …):
   body schema ở trên là SUY ĐOÁN từ i18n + mock data. Validate trên tài khoản
   thử nghiệm trước khi triển khai production.

MỤC 10 — PARITY v2.0: MỌI ENDPOINT HOẠT ĐỘNG NHƯ FLOW EARN (tool v2.0)
================================================================================

Tool v2.0 áp dụng toàn bộ tiêu chuẩn của flow earn-coin cho CẢ 82 endpoint
(ngoại trừ endpoint chỉ admin — server sẽ trả 403 và tool tự đề nghị ẩn):

1. HEADERS TỰ ĐỘNG ĐỦ — interceptor embedded gắn x-ts + x-sign + Bearer +
   Content-Type + Origin + Referer + UA trên MỌI request (đã field-test).
   Panel "Chi tiết lỗi" luôn in lại headers đã gửi để tự kiểm chứng.

2. MESSAGE NGHIỆP VỤ + GỢI Ý (GENERAL_HINTS) — mọi response có `message`
   đều hiện panel nổi; các nhóm message thường gặp có gợi ý xử lý sẵn:
   - unauthenticated / chưa đăng nhập / hết hạn → đăng nhập lại (mục 1)
   - thao tác hơi nhanh / too many              → rate-limit, chờ rồi thử
   - không đủ                                   → thiếu coin, earn/nạp thêm
   - captcha / recaptcha                        → hướng dẫn lấy token v3 từ web
   - đã tồn tại / not found / không tìm thấy    → trùng / sai id
   - admin / forbidden / không có quyền         → chỉ admin (tool đề nghị ẩn)
   - tham quan (demo), điều khoản/terms, chưa kích hoạt, hết quota...

3. 429 TỰ ĐẾM NGƯỢC — đọc retry_after (gốc hoặc trong data), đếm ngược
   động với thanh tiến trình, đúng như web.

4. FIELD_GUIDE — trước khi điền form, tool in hướng dẫn từng endpoint:
   id lấy ở đâu (Order list → cancel/refill; Referral commissions → claim;

   "sai mạng ví = mất tiền" (crypto),captcha lấy từ DevTools (add/register)...

5. ĐIỀN FORM AN TOÀN — trường có tập giá trị cố định thành menu chọn:
   type/platform (tiktok|facebook), telco (Viettel|MobiFone|VinaPhone),
   network (bep20|trc20|erc20), category (withdraw|deposit|account|other).

6. ENDPOINT CHỈ ADMIN — server trả 403 hoặc message 'admin/forbidden/
   không có quyền' → tool hiện gợi ý + hỏi "Ẩn endpoint này khỏi menu
   (phiên này)?" → lần sau không còn hiện (chỉ admin mới thấy được).

7. CHẠY LẠI NHANH — sau mỗi kết quả: Enter = về danh sách · j = JSON thô ·
   e = chạy lại endpoint này (thử giá trị khác không phải chọn lại từ đầu).

8. CLEAR TOÀN BỘ MÀN HÌNH — clear_screen gửi \033[2J + \033[3J + \033[H:
   xoá cả vùng nhìn thấy LẪN SCROLLBACK (lịch sử cuộn), hoạt động trên
   xterm/GNOME/Windows Terminal/iTerm2/Termux; Windows legacy bật VT qua
   os.system(""). Env F4F_NO_ANIM=1 tắt hiệu ứng nếu cần.
